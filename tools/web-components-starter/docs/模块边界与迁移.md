# 现有工作台接下来怎样迁移

1. 将旧工程作为参考保留；新工程使用自己的依赖清单，不从旧聊天目录取 node_modules。
2. 从旧 app.js 提取 importer、normalizer、material-registry、view-renderer、vectorizer、svg-exporter、project-settings，先不改变输出行为。
3. 以 `core/contracts.ts` 为起点完善接口。统一输出 GLB，并将几何、材质、贴图差异写入报告；差异是否合理需要逐项解释。
4. UI 分为 ModelDropzone、ConversionStatus、ViewSelector、MaterialEditor、VectorPreview、ExportPanel。当前仅实现了 ViewSelector 示例。
5. CAD 和 Assimp 分别运行于独立 Worker；设置取消、错误反馈和任务序号，防止旧任务覆盖新任务。
6. 以真实 GLB、OBJ+MTL、STL、STEP 样本分别测试；FBX、BLEND 等不能因为依赖声称支持就标记为验证通过。
7. 记录六面视角、完整材质分组、无位图 SVG、曲线节点数与 Logo 保留情况。用图片与 SVG 人工核验，不只看统计值。

## 首批必须避免的问题

- 转换前后用错同一个文件作验证，导致看似“校验通过”。
- 任务处理中继续允许修改相机或材料，输出与界面设置不一致。
- SVG 已过期却仍显示“最新”，或把上一个角度的标签加入当前角度。
- 同一模型不同材质的可见性只按整个 Mesh 切换。
- 采用几何遮罩时丢失顶盖的贴图 Logo，却仍声称外观符合要求。
- 将大型源模型、node_modules 或带会话信息的下载地址提交到公共仓库。

## 当前策略

单项目、清楚分层、先真实验证。暂不需要微服务、数据库、复杂多包工具或自动发布平台。Storybook 和 Changesets 有具体复用 / 发布需求时再引入。
